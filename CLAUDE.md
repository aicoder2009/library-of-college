# Library of College

A college-essay evidence bank ("Library of College", short "LoC" — formerly "Archive", originally "Evidence Bank"; the name riffs on Library of Congress) for collecting stories/details and mining them while drafting supplementals. Single-user personal project (user details in `CLAUDE.local.md`, gitignored). Live at **https://liboc.vercel.app** (older aliases from previous names still point at the same deployment so nothing bookmarked breaks; a short-lived `thearchival.vercel.app` alias was released). Note: `loc.vercel.app` and `archive.vercel.app` were already taken by unrelated sites — `liboc.vercel.app` was the chosen unclaimed alias. `liboc.vercel.app` is attached as a project *domain* (2026-08-16), so `vercel deploy --prod` moves it automatically — before that it was a manually-pinned alias and prod deploys silently never reached it. Team-scoped deployment URLs are subject to Vercel's default SSO/Deployment Protection on non-custom domains; project-level SSO protection was disabled (`vercel project protection disable library-of-college --sso`) so deployment URLs resolve publicly. This doesn't expose user data — the app is still gated behind Clerk login.

## Architecture

- **Frontend**: three single-file pages, no build step, no framework, no external resources except ClerkJS (app + login only). `index.html` = the public marketing/landing page at `/` (SaaS layout, waitlist signup form → `POST /waitlist`; reuses the app's design tokens verbatim — keep the palettes in sync). `login.html` = the sign-in page at `/login` (noindex): mounts the themed Clerk card, `waitlistUrl: "/"`, and `mountSignIn` pins `fallbackRedirectUrl`/`forceRedirectUrl` to `/app`; already-signed-in visitors are bounced to `/app`. `app.html` = the entire app, served at `/app` via `vercel.json` `cleanUrls: true` (`manifest.webmanifest` `start_url` is `/app`); signed-out visitors to `/app` are redirected to `/login` (the in-app lock screen now only covers loading and the not-allowlisted 401 state). Landing "Log in" links point to `/login`; the localStorage returning-owner nicety rewrites them to `/app`. Deployed as a static site on Vercel (project `library-of-college`, renamed from `archive`, originally `evidence-bank`; already linked via `.vercel/`).
- **Backend**: `backend/index.mjs` — one AWS Lambda (`evidence-bank-api`, Node 20, us-east-1) behind API Gateway HTTP API at `https://3abskrlijk.execute-api.us-east-1.amazonaws.com`. Routes: `GET/PUT /entries` (whole-state sync), `POST /title` (AI title), `POST /classify` (AI title + categories), `POST /match` (prompt → best-fitting entries with `fit` strong/possible + concrete `why`; with `deep:true` — the frontend's ✦ Breakdown switch, on by default — also returns `deconstruction`, `college`+`college_advice` (school identified from the prompt's own wording, empty strings when unsure — advice only ships alongside a named school), `gap_analysis`, `outline`), `POST /search` (⌘K Ideas tab: idea/semantic search → related entries + short `why`), `POST /polish` (AI grammar tidy, session-only), `POST /waitlist` (PUBLIC — the only unauthenticated route, handled before the auth gate; validates/normalizes the email, 400-byte body cap, 2000-signup cap, returns `{ok,position}` or `{ok,dup,position}`), `GET /waitlist` (authed; returns the signup list). OPTIONS returns 204 (CORS preflights fall through to the Lambda — do not remove this). The Lambda's IAM role allows ONLY `dynamodb:GetItem/PutItem/DeleteItem` — no UpdateItem/Scan/Query (and IAM edits are blocked by the permission classifier), so any new server feature must be built read-modify-write on whole items.
- **Data**: DynamoDB table `evidence-bank` (us-east-1), MULTI-TENANT since 2026-08-26: each account's library is one item — owner accounts (IDs in `ALLOWED_USER_ID`) use the original `pk=data` (+ `backup#YYYY-MM-DD` snapshots, no migration ever ran), every other Clerk user uses `pk=data#<clerk_user_id>` (+ `backup#<clerk_user_id>#YYYY-MM-DD`). `ALLOWED_USER_ID` is no longer the access gate (any signed-in Clerk user gets a library; account creation is gated by Clerk waitlist approval) — it now means "owner/admin": maps to the founding library and guards `GET /waitlist` (403 otherwise). Each library item holds the full state JSON: `{entries:[{id,title,body,cats:[0-6],pinned,tags,createdAt,updatedAt}],prompts:[{id,q,sch,createdAt}],rev,backupRev}` (`prompts` = the user-editable "school prompt map" on the Why School page — ships empty in code, seeded/edited by the user; used-in tag derives from the first `·`/`,`-separated segment of `sch`). Whole-state PUT with optimistic concurrency: the Lambda 409s (`{error:"stale",rev}`) any PUT whose `rev` isn't ahead of the stored rev (also 409s a PUT that would shrink a ≥10-entry library by more than half — wipe protection); the write itself is a conditional PutItem guarded on a top-level `rev` N attribute (kept in lockstep with the JSON's `rev` — never write one without the other); the client then GETs, merges by entry id (newer `updatedAt` wins, nothing dropped), and re-PUTs with `rev = max+1` (`mergeSync()` in index.html). Once per day the pre-change state is snapshotted to `backup#YYYY-MM-DD` items, reaped by DynamoDB TTL after ~15 days (table TTL is enabled on attribute `ttl`). Waitlist signups live in a separate single item `pk=waitlist` (`{rev:N, list:S}` — JSON array of `{email,at}`, optimistic-concurrency via conditional put on `rev`, one retry). Point-in-time recovery is enabled on the table. THIS IS THE USER'S REAL DATA — never overwrite it blindly; read-merge-write if editing server-side.
- **Auth**: Clerk, TWO instances since 2026-08-29. `liboc.vercel.app` runs the PRODUCTION instance (`pk_live` key, sign-up mode "waitlist"); because liboc.vercel.app is a vercel.app subdomain (no CNAME possible), the prod Frontend API is proxied through `/__clerk` — a Vercel edge function (`api/clerk-proxy.mjs`, rewrite in `vercel.json`) that forwards to `frontend-api.clerk.dev` with `Clerk-Proxy-Url`/`Clerk-Secret-Key` headers (`CLERK_SECRET_KEY` sk_live lives in the Vercel project env, never the repo). Prod session JWTs carry `iss=https://liboc.vercel.app/__clerk`. Localhost and the legacy aliases stay on the DEV instance (`lasting-falcon-91.clerk.accounts.dev`) — the frontend picks key + load URL by hostname (`CLERK_LIVE` in `app.html`/`login.html`). The Lambda accepts a comma-separated `CLERK_ISSUER` list (dev issuer + prod proxy URL, per-issuer JWKS cache) and its `CLERK_SECRET_KEY` is now the sk_live key (waitlist mirroring targets the prod instance). `ALLOWED_USER_ID` (owner allowlist, comma-separated) holds the owner's dev AND prod user IDs — both map to the founding `pk=data` library; the specific IDs are in `CLAUDE.local.md`. The Clerk CLI is installed and logged in; project is linked (`clerk whoami`).
- **AI**: OpenAI via `OPENAI_API_KEY` in the Lambda env (server-side only — never put the key in the frontend). Model split: `gpt-5.6-sol` for `/match` (reasoning_effort low) and `/search` (reasoning_effort none — interactive); cheap `gpt-4.1-nano`/`gpt-4.1-mini` for `/title`, `/classify`, `/polish`. GPT-5.x on Chat Completions needs `max_completion_tokens` (not `max_tokens`) and rejects non-default `temperature`.
- **AWS access**: SSO profile with admin access — profile name and account ID in `CLAUDE.local.md`. If expired: user runs `aws sso login --profile <profile>`.

## Commands

- **Deploy frontend**: `vercel deploy --prod --yes` — ALWAYS from this folder, NEVER from `backend/` (doing so once created a stray Vercel project that had to be deleted).
- **Deploy backend**: `cd backend && rm -f fn.zip && zip -q fn.zip index.mjs && AWS_PROFILE=<profile from CLAUDE.local.md> aws lambda update-function-code --function-name evidence-bank-api --zip-file fileb://fn.zip && aws lambda wait function-updated-v2 --function-name evidence-bank-api`
- **Verify JS before any deploy** (no test suite exists): `awk '/<script>/{f=1;next}/<\/script>/{f=0}f' <file> > /tmp/x.js && node --check /tmp/x.js` for BOTH `index.html` and `app.html`, plus `node --check backend/index.mjs`
- Lambda env vars (TABLE, CLERK_ISSUER, ALLOWED_USER_ID, OPENAI_API_KEY) are set on the function; changing them: `aws lambda update-function-configuration` with a `--cli-input-json` file so the key never lands in shell history.

## App conventions (established with the user — don't relitigate)

- Categories are fixed indices with fixed colors: 0 Community/Perspective, 1 Leadership, 2 Why School, 3 Why Major (sidebar group "Supplementals"); 4 Creative, 5 Problem-solver, 6 My favorite topic (group "About me · UC PIQs"). Entries can be in multiple categories only when each genuinely fits.
- Design language: warm paper palette (CSS variables, full dark-mode parity required for every color), serif reading view, highlighter-stroke category headings (.hl), luggage-tag chips (.rtag), sidebar nav + centered reading column, expand-in-place rows, slide-over composer, ⌘K palette (two tabs, Tab key switches: Verbatim = literal word-AND text match; ✦ Ideas = AI semantic search via `/search`, runs on Enter), quick-dump modal (`d`), per-category multiline dump bars. The user explicitly rejected kanban boards and stacked-section layouts — never change the layout paradigm.
- `tags` = "used-in" tracker (which essay/school an entry was used for), not general labels.
- Shortcuts: ⌘K palette, d dump modal, n composer, / search, ↑↓/j/k review, ⌘Enter save, Escape cascade (palette → dump → composer → collapse → tag filter → search).

## Gotchas

- API hardening (2026-08-26): API Gateway CORS is an origin ALLOWLIST (liboc.vercel.app, the two old aliases, http://localhost:8765) and the Lambda rejects session JWTs whose `azp` isn't in the matching `AZP` set in `backend/index.mjs` — if the frontend ever moves to a new domain, add it in BOTH places or every API call 401s. Stage default throttle 10 rps / burst 25; AI routes budget 30 calls per 5 min per user (in-memory, resets on cold start); raw bodies over 500KB get 413; OpenAI fetches abort at 25s, under the Lambda's 28s timeout (raised from 10s on 2026-08-29 so a deep `/match` returns a clean 502 instead of a raw Lambda timeout; API Gateway's fixed 30s cap sits above both).

- This repo is public. `CLAUDE.local.md` (gitignored) holds the private details — user identity, Clerk app ID, AWS account/profile, allowlisted users. Never move any of that back into committed files, and keep new commits authored with the repo-local git identity (already configured).
- Icons/`og-image.png` (bold serif "L" behind an orange highlighter stripe, matching the in-app `.hl` category-heading style) are generated by `tools/genicons.py` (Pillow, samples its palette from the existing icons) — rerun it rather than hand-edit if the wordmark changes. `og-image.png` and the favicon/`apple-touch-icon`/`icon-*` PNGs are referenced by absolute/root-relative URLs in `index.html`'s `<head>` (og:image points at `https://liboc.vercel.app/og-image.png` specifically — update it if the canonical domain ever changes).
- Only user-facing branding was renamed to "Library of College" (frontend copy, icons, Vercel project + URL, Clerk app display name, GitHub repo, local folder, localStorage keys now `liboc-*`). The backend Lambda (`evidence-bank-api`), its IAM role (`evidence-bank-lambda`), and the DynamoDB table (`evidence-bank`) deliberately keep their original names — renaming them is internal churn with real risk to the live data path, and the required IAM writes are blocked by the permission classifier anyway (a table copy made during the 2026-08 rename attempt was rolled back).
- `.env.clerk` holds the Clerk SECRET key — it is `.vercelignore`d and gitignored; keep it that way.
- Browser testing via the Claude Chrome extension: global shortcuts fire on stray typing (click into a field first), navigation restores scroll position (screenshot before clicking), and any test entries created must be deleted afterward.
- Clerk prod cutover (2026-08-29): `liboc.vercel.app` uses the prod instance via the `/__clerk` proxy (see Auth). NOT yet done on prod: custom Google OAuth credentials (Clerk requires them in production — Google sign-in on liboc fails until they're added in the Clerk dashboard); the dev instance still serves localhost + legacy aliases. `sw.js` deliberately never intercepts `/__clerk/*` (same-origin now) — keep that exclusion. The proxy function must relay Set-Cookie headers individually (`getSetCookie()`), and strips content-encoding/length (fetch decompresses).
- localStorage (`liboc-v1`) is only a cache; the server state wins at boot.
