# Library of College

A college-essay evidence bank ("Library of College", short "LoC" — formerly "Archive", originally "Evidence Bank"; the name riffs on Library of Congress) for collecting stories/details and mining them while drafting supplementals. Single-user personal project (user details in `CLAUDE.local.md`, gitignored). Live at **https://liboc.vercel.app** (older aliases from previous names still point at the same deployment so nothing bookmarked breaks; a short-lived `thearchival.vercel.app` alias was released). Note: `loc.vercel.app` and `archive.vercel.app` were already taken by unrelated sites — `liboc.vercel.app` was the chosen unclaimed alias. `liboc.vercel.app` is attached as a project *domain* (2026-08-16), so `vercel deploy --prod` moves it automatically — before that it was a manually-pinned alias and prod deploys silently never reached it. Team-scoped deployment URLs are subject to Vercel's default SSO/Deployment Protection on non-custom domains; project-level SSO protection was disabled (`vercel project protection disable library-of-college --sso`) so deployment URLs resolve publicly. This doesn't expose user data — the app is still gated behind Clerk login.

## Architecture

- **Frontend**: three single-file pages, no build step, no framework, no external resources except ClerkJS (app + login only). `index.html` = the public marketing/landing page at `/` (SaaS layout, waitlist signup form → `POST /waitlist`; reuses the app's design tokens verbatim — keep the palettes in sync). `login.html` = the sign-in page at `/login` (noindex): mounts the themed Clerk card, `waitlistUrl: "/"`, and `mountSignIn` pins `fallbackRedirectUrl`/`forceRedirectUrl` to `/app`; already-signed-in visitors are bounced to `/app`. `app.html` = the entire app, served at `/app` via `vercel.json` `cleanUrls: true` (`manifest.webmanifest` `start_url` is `/app`); signed-out visitors to `/app` are redirected to `/login`. Signed-in boot (2026-08-29): a warm per-account cache paints the library immediately while the first sync runs; on a cold cache the "Opening the library…" lock screen stays up until that sync settles; a 401 sets `authBlocked` so `boot()` never drops the not-allowed screen. Landing "Log in" links point to `/login`; the localStorage returning-owner nicety rewrites them to `/app`. Deployed as a static site on Vercel (project `library-of-college`, renamed from `archive`, originally `evidence-bank`; already linked via `.vercel/`).
- **Backend**: `backend/index.mjs` — one AWS Lambda (`evidence-bank-api`, Node 24, us-east-1) behind API Gateway HTTP API at `https://3abskrlijk.execute-api.us-east-1.amazonaws.com`. Routes: `GET/PUT /entries` (whole-state sync), `POST /title` (AI title), `POST /classify` (AI title + categories), `POST /match` (prompt → best-fitting entries with `fit` strong/possible + concrete `why`; with `deep:true` — the frontend's ✦ Breakdown switch, on by default — also returns `deconstruction`, `college`+`college_advice` (school identified from the prompt's own wording, empty strings when unsure — advice only ships alongside a named school), `gap_analysis`, `outline`), `POST /search` (⌘K Ideas tab: idea/semantic search → related entries + short `why`), `POST /polish` (AI grammar tidy, session-only), `POST /waitlist` (PUBLIC — the only unauthenticated route, handled before the auth gate; validates/normalizes the email, 400-byte body cap, 2000-signup cap, returns `{ok,position}` or `{ok,dup,position}`), `GET /waitlist` (authed; returns the signup list). OPTIONS returns 204 (CORS preflights fall through to the Lambda — do not remove this). The Lambda's IAM role allows ONLY `dynamodb:GetItem/PutItem/DeleteItem` — no UpdateItem/Scan/Query — plus `sts:GetWebIdentityToken` restricted to audience `https://api.anthropic.com` (inline policy `anthropic-wif`, for Claude's workload identity). IAM edits are usually blocked by the permission classifier, so any new server feature must be built read-modify-write on whole items.
- **Data**: DynamoDB table `evidence-bank` (us-east-1), MULTI-TENANT since 2026-08-26: each account's library is one item — owner accounts (IDs in `ALLOWED_USER_ID`) use the original `pk=data` (+ `backup#YYYY-MM-DD` snapshots, no migration ever ran), every other Clerk user uses `pk=data#<clerk_user_id>` (+ `backup#<clerk_user_id>#YYYY-MM-DD`). `ALLOWED_USER_ID` is no longer the access gate (any signed-in Clerk user gets a library; account creation is gated by Clerk waitlist approval) — it now means "owner/admin": maps to the founding library and guards `GET /waitlist` (403 otherwise). Each library item holds the full state JSON: `{entries:[{id,title,body,cats:[0-6],pinned,tags,createdAt,updatedAt}],prompts:[{id,q,sch,due,limit,status,picks,createdAt,updatedAt}],trash:[{...entry,deletedAt}],deleted:{id:ts},rev,backupRev}`. `prompts` = the Essays page (user-entered prompts with deadline `due` "YYYY-MM-DD", word `limit`, `status` todo/drafting/done, `picks` = entry ids; prompts saved before 2026-11 have only `{id,q,sch,createdAt}` and every reader copes; the used-in tag derives from the first `·`/`,`-separated segment of `sch`, and picking a story adds that tag). `trash` = Recently deleted (pruned client-side to 30 days / 100 items / ~80KB); `deleted` = tombstones for removed entries and prompts (pruned after 120 days). The Lambda stores and returns the body verbatim, so new fields need no backend change. Whole-state PUT with optimistic concurrency: the Lambda 409s (`{error:"stale",rev}`) any PUT whose `rev` isn't ahead of the stored rev (also 409s a PUT that would shrink a ≥10-entry library by more than half, not counting entries the PUT itself tombstones in `deleted` — wipe protection; and, once a library has a `deleted` object, 409s any PUT without one — that locks out app tabs still running pre-2026-11 code, which would otherwise write back copies with no trash/tombstones); the write itself is a conditional PutItem guarded on a top-level `rev` N attribute (kept in lockstep with the JSON's `rev` — never write one without the other). Client sync (since 2026-11): `state.rev` is the server revision the local copy is based on (never bumped per edit) and a `_dirty` flag rides beside the localStorage cache only (stripped, never sent); every PUT claims `rev+1`, so any device that hasn't seen the latest write gets a 409, GETs, merges with `mergeStates()` (newest `updatedAt` wins per entry/prompt, tombstones beat older copies, an edit newer than its tombstone wins) and retries. `boot()` merges only when the cache is dirty (caches from before the flag fall back to the old local-rev-ahead check); returning to the tab pulls when nothing is pending. Restoring a `backup#…` snapshot by hand: write it back with `rev` above the live one (e.g. +1000) so open tabs pull it instead of overwriting it, bump `updatedAt` on any restored entry/prompt that a tombstone in `deleted` would otherwise drop (or delete that tombstone), then reload every device. Once per day the pre-change state is snapshotted to `backup#YYYY-MM-DD` items, reaped by DynamoDB TTL after ~15 days (table TTL is enabled on attribute `ttl`). Waitlist signups live in a separate single item `pk=waitlist` (`{rev:N, list:S}` — JSON array of `{email,at}`, optimistic-concurrency via conditional put on `rev`, one retry). Point-in-time recovery is enabled on the table. THIS IS THE USER'S REAL DATA — never overwrite it blindly; read-merge-write if editing server-side.
- **Auth**: Clerk, TWO instances since 2026-08-29. `liboc.vercel.app` runs the PRODUCTION instance (`pk_live` key, sign-up mode "waitlist"); because liboc.vercel.app is a vercel.app subdomain (no CNAME possible), the prod Frontend API is proxied through `/__clerk` — a Vercel edge function (`api/clerk-proxy.mjs`, rewrite in `vercel.json`) that forwards to `frontend-api.clerk.dev` with `Clerk-Proxy-Url`/`Clerk-Secret-Key` headers (`CLERK_SECRET_KEY` sk_live lives in the Vercel project env, never the repo). Prod session JWTs carry `iss=https://liboc.vercel.app/__clerk`. Localhost and the legacy aliases stay on the DEV instance (`lasting-falcon-91.clerk.accounts.dev`) — the frontend picks key + load URL by hostname (`CLERK_LIVE` in `app.html`/`login.html`). The Lambda accepts a comma-separated `CLERK_ISSUER` list (dev issuer + prod proxy URL, per-issuer JWKS cache) and its `CLERK_SECRET_KEY` is now the sk_live key (waitlist mirroring targets the prod instance). `ALLOWED_USER_ID` (owner allowlist, comma-separated) holds the owner's dev AND prod user IDs — both map to the founding `pk=data` library; the specific IDs are in `CLAUDE.local.md`. The Clerk CLI is installed and logged in; project is linked (`clerk whoami`). `login.html` intercepts OAuth callbacks for unknown accounts (`handleUninvitedOauth`): in waitlist mode the prebuilt card's sign-up transfer throws, so instead the page auto-adds the Google email to the waitlist via `POST /waitlist` (best-effort) and shows a friendly "you're on the waitlist" screen; Clerk error copy for the typed-email/restricted paths is overridden via `Clerk.load({localization})`.
- **AI**: Claude through the Anthropic SDK (`@anthropic-ai/sdk`, pinned in `backend/package.json` — the backend's only bundled dependency), signed in with Workload Identity Federation: NO API key exists anywhere. The Lambda role mints a 5-minute AWS STS web identity token (audience `https://api.anthropic.com`; AWS outbound identity federation is enabled on the account) and the SDK's `oidcFederationProvider` exchanges it at `/v1/oauth/token` for a short-lived Claude token that it caches and refreshes. The Claude Console (Keys & access → Workload identity) holds the registered AWS issuer, the `liboc-lambda` service account and the federation rule (subject = the Lambda role ARN, exact match; scope `workspace:inference`). Their IDs are the Lambda env vars `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `ANTHROPIC_SERVICE_ACCOUNT_ID` (identifiers, not secrets; values in `CLAUDE.local.md`). Only that role satisfies the rule, so the AI chain can't be exercised from a laptop — test through the deployed API or a throwaway Lambda with the same role. The SDK is imported lazily inside the AI routes, so a packaging problem can't take sync down. Every request sends `inference_geo: "us"` (the owner wants processing kept in the US; 1.1x price) and `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`: a safety-classifier refusal reruns on Anthropic's recommended model; only text after the last `fallback` block counts). Model: `claude-opus-5-5` on every route; its thinking can't be turned off, so `output_config.effort` is the latency/cost dial — low for /title, /classify, /polish, medium for /match, high for /search. JSON routes use structured outputs (`output_config.format`, json_schema — no `enum`: allowed values go in descriptions and the route validates). Thinking is always on and counts toward `max_tokens`, so caps are generous. Each call logs one JSON line (route, model, ms, tokens, inference geo); failures log status/name only, never note text.
- **AWS access**: SSO profile with admin access — profile name and account ID in `CLAUDE.local.md`. If expired: user runs `aws sso login --profile <profile>`.

## Commands

- **Deploy frontend**: `vercel deploy --prod --yes` — ALWAYS from this folder, NEVER from `backend/` (doing so once created a stray Vercel project that had to be deleted).
- **Deploy backend**: `cd backend && npm ci --omit=dev && rm -f fn.zip && zip -qr fn.zip index.mjs package.json node_modules && export AWS_PROFILE=<profile from CLAUDE.local.md> && aws lambda update-function-code --function-name evidence-bank-api --zip-file fileb://fn.zip && aws lambda wait function-updated-v2 --function-name evidence-bank-api` (the AWS SDK comes with the runtime; only the Anthropic SDK is bundled, ~6MB zipped). Right after a deploy, smoke-test sync (GET /entries) as well as an AI route.
- **Verify JS before any deploy**: `awk '/<script>/{f=1;next}/<\/script>/{f=0}f' <file> > /tmp/x.js && node --check /tmp/x.js` for BOTH `index.html` and `app.html`, plus `node --check backend/index.mjs`, plus `node tests/app.test.mjs` (runs app.html's real script in Node vm "devices" against a fake server with the Lambda's sync rules — sync/merge/tombstones, Essays, trash, import/export, every view rendering; no deps; CI runs it too). It stubs the DOM, so focus, CSS and real browser behavior still need a click-through.
- **Deploys happen on merge**: the Vercel project is Git-linked (production branch `main`), so merging to `main` deploys production and moves every project domain (liboc.vercel.app and the legacy aliases); pushed branches get preview URLs, which the API's CORS allowlist rejects. `vercel deploy --prod --yes` still works for out-of-band deploys.
- Lambda env vars (TABLE, CLERK_ISSUER, ALLOWED_USER_ID, CLERK_SECRET_KEY, ANTHROPIC_FEDERATION_RULE_ID, ANTHROPIC_ORGANIZATION_ID, ANTHROPIC_SERVICE_ACCOUNT_ID) are set on the function. `--environment` REPLACES the whole map: read the current config, merge, and apply with `aws lambda update-function-configuration --cli-input-json file://…` so the Clerk secret never lands in shell history or output.

## App conventions (established with the user — don't relitigate)

- Categories are fixed indices with fixed colors: 0 Community/Perspective, 1 Leadership, 2 Why School, 3 Why Major (sidebar group "Supplementals"); 4 Creative, 5 Problem-solver, 6 My favorite topic (group "About me · UC PIQs"). Entries can be in multiple categories only when each genuinely fits.
- Design language: warm paper palette (CSS variables, full dark-mode parity required for every color), serif reading view, highlighter-stroke category headings (.hl), luggage-tag chips (.rtag), sidebar nav + centered reading column, expand-in-place rows, slide-over composer, ⌘K palette (two tabs, Tab key switches: Verbatim = literal word-AND text match; ✦ Ideas = AI semantic search via `/search`, runs on Enter), quick-dump modal (`d`), per-category multiline dump bars. The user explicitly rejected kanban boards and stacked-section layouts — never change the layout paradigm.
- `tags` = "used-in" tracker (which essay/school an entry was used for), not general labels.
- Non-category pages render into the same reading column via `page` (`"essays"` | `"trash"`), with `nav` keeping the last category: **Essays** (sidebar item under the top actions; its count slot shows days to the nearest open deadline and turns `.thin` within a week — still no badges; prompt rows are `.entry.prow` with expand-in-place, deadline/limit fields commit via `persistSoft()` so the input keeps focus) and **Recently deleted** (`.entry.trow`, sidebar item shown only while non-empty). Why School links to Essays and hosts the "clip from websites" bookmarklet guide (the clip arrives as `/app#clip=…`, stashed to sessionStorage before the Clerk redirect, opened in the composer by `boot()`). Inline inputs inside re-rendered markup carry `data-keep` so `render()` preserves their text and focus.
- Shortcuts: ⌘K palette, d dump modal, n composer, / search, ↑↓/j/k review, ⌘Enter save, Escape cascade (palette → dump → composer → collapse → tag filter → search).

## Gotchas

- API hardening (2026-08-26): API Gateway CORS is an origin ALLOWLIST (liboc.vercel.app, the old evidence-bank.vercel.app alias, http://localhost:8765) and the Lambda rejects session JWTs whose `azp` isn't in the matching `AZP` set in `backend/index.mjs` — if the frontend ever moves to a new domain, add it in BOTH places or every API call 401s. Stage default throttle 10 rps / burst 25; AI routes budget 30 calls per 5 min per user (in-memory, resets on cold start); raw bodies over 500KB get 413; Claude requests time out at 24s (one attempt, no SDK retries), under the Lambda's 28s timeout (raised from 10s on 2026-08-29 so a deep `/match` returns a clean 502 instead of a raw Lambda timeout; API Gateway's fixed 30s cap sits above both).

- This repo is public. `CLAUDE.local.md` (gitignored) holds the private details — user identity, Clerk app ID, AWS account/profile, allowlisted users. Never move any of that back into committed files, and keep new commits authored with the repo-local git identity (already configured).
- The design system lives in `docs/design-system/` (brand book, `tokens.json`, generated `tokens.css`, seventeen components with previews, the marks) and is mirrored as a published design-system artifact. `tokens.json` is the source of truth; `python3 tools/gentokens.py` rewrites `tokens.css` from it. The three pages deliberately keep their tokens inline — changing a token means editing `tokens.json`, rerunning the generator, AND updating the `:root` blocks in `index.html`, `login.html` and `app.html`. Do not link `tokens.css` from a shipping page; the no-external-stylesheet rule stands.
- Icons/`og-image.png` (bold serif "L" behind an orange highlighter stripe, matching the in-app `.hl` category-heading style) are generated by `tools/genicons.py` (Pillow, samples its palette from the existing icons) — rerun it rather than hand-edit if the wordmark changes. `og-image.png` and the favicon/`apple-touch-icon`/`icon-*` PNGs are referenced by absolute/root-relative URLs in `index.html`'s `<head>` (og:image points at `https://liboc.vercel.app/og-image.png` specifically — update it if the canonical domain ever changes).
- Only user-facing branding was renamed to "Library of College" (frontend copy, icons, Vercel project + URL, Clerk app display name, GitHub repo, local folder, localStorage keys now `liboc-*`). The backend Lambda (`evidence-bank-api`), its IAM role (`evidence-bank-lambda`), and the DynamoDB table (`evidence-bank`) deliberately keep their original names — renaming them is internal churn with real risk to the live data path, and the required IAM writes are blocked by the permission classifier anyway (a table copy made during the 2026-08 rename attempt was rolled back).
- `.env.clerk` holds the Clerk SECRET key — it is `.vercelignore`d and gitignored; keep it that way.
- Browser testing via the Claude Chrome extension: global shortcuts fire on stray typing (click into a field first), navigation restores scroll position (screenshot before clicking), and any test entries created must be deleted afterward.
- Clerk prod cutover (2026-08-29): `liboc.vercel.app` uses the prod instance via the `/__clerk` proxy (see Auth). NOT yet done on prod: custom Google OAuth credentials (Clerk requires them in production — Google sign-in on liboc fails until they're added in the Clerk dashboard); the dev instance still serves localhost + legacy aliases. `sw.js` deliberately never intercepts `/__clerk/*` (same-origin now) — keep that exclusion. The proxy function must relay Set-Cookie headers individually (`getSetCookie()`), and strips content-encoding/length (fetch decompresses).
- localStorage is only a cache and is keyed per account once Clerk resolves (`liboc-v1:<clerk_user_id>`, same pattern for `liboc-ui:`/`liboc-draft:`; the bare `liboc-*` keys are just the signed-out defaults). It paints first on a warm boot, but the server state still wins once the first sync lands.
